# I18N — PortScope localisation

> Phase 0 draft. Target: gettext `.po`. **The `.po` catalogue does not exist
> yet** — the Spike used an exhaustive Rust string table, which Phase 3 replaces.

## 1. Requirements

- English and Simplified Chinese are complete in the first release.
- Default follows the system locale; unsupported locales fall back to English.
- A manual choice overrides the system default **and survives restart**.
- Switching language updates the current page immediately while preserving the
  selected object, search text, filters, and scroll position where meaningful.
- Every user-visible string comes from the catalogue — **no hardcoded UI text in
  widget-construction code**.
- Translation completeness and extraction are CI-checked.
- Raw technical data is never translated.

## 2. Never translated (verbatim)

IP addresses, ports, PID/PPID/UID numbers, process names, unit names, cgroup
paths, command lines, raw journal text, protocol identifiers (`TCP`, `UDP`,
`LISTEN`, `UNCONN`, `active`, `failed`), and the file/unit suffixes
(`.service`, `.socket`, `.scope`).

Translated: interface labels, state descriptions, error explanations, help text,
buttons, menus, user-visible date/duration expressions, and PortScope's own
diagnostic interpretations.

## 3. Technical identifiers kept in English by design

`PID`, `PPID`, `UID`, `cgroup`, and the language endonyms `English` / `简体中文`
(the last two are conventionally shown in their own language).

## 4. Messages and plurals

- Complete message entries; never build a sentence by concatenating fragments
  (word order and CJK differ).
- Plurals use gettext plural forms (`nplurals=1` for Chinese, `2` for English) —
  e.g. endpoint counts in the status bar.
- Every entry carries a context comment where the term is ambiguous
  (e.g. "State" as socket state vs unit state vs lifecycle state).
- Placeholders are named (`%(port)s`) so translators can reorder them.

## 5. Runtime switching — the known hard part

The Spike proved empirically that `setlocale` **does** change the language at
runtime but that **already-rendered widgets keep their old text**. Therefore a
language switch must rebuild or re-bind visible widgets. That is permitted by
taskbook §9.7, but the user's current object, filters and search must survive.

Phase 3 must not regress the state-preservation behaviour demonstrated by the
Spike screenshots (`08-en-ports-dark-details.png` → `09-zh-ports-dark-details.png`).

## 7. Quality checks required in CI

1. All source strings extracted (`msgfmt` + custom extraction check).
2. No missing or fuzzy entries in `zh_CN`.
3. `.po` files parse (`msgfmt --check-format`).
4. No untranslated ASCII-only values left in Chinese entries where translation
   is required (carried over from the Spike's leak test).
5. Raw technical values are asserted unchanged in both languages.
6. No user-visible string exists outside the catalogue (grep/AST check).

## 8. Manual verification still owed
